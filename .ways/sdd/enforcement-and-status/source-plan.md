# Goal

Make harness compliance mechanical instead of prompt-dependent, and expose the
active mode as a stable artifact that any agent statusline can read without
starting Node. Flexible means choosing the ceremony, never skipping it.

Today integrity only validates state against Git when `.ways/state/current.json`
exists. Without an active work, manual commits pass every check. This plan closes
that hole and prepares the ground for provider adapters.

# Plan

1. Add `.ways/status.json`: a reduced, stable summary (mode, id, phase, profile,
   humanGate, status, gateCommit) regenerated by `saveState` and `removeState`.
   Integrity fails if it diverges from `current.json`. Add `ways status --json`
   printing the same contract.
2. Add `Harness-*` trailer verification to integrity: with active state, HEAD
   commits since `baseCommit` must carry `Harness-Work` matching the work id.
3. Add `ways check --history [--since=<ref>]`: every commit since the ref must
   carry `Harness-Work` and `Harness-State`, and every `sdd` certification must
   chain to its previous phase. Wire it into `scripts/check.sh` for CI.
4. Install Git hooks from bootstrap as managed files under `.ways/hooks/` and set
   `core.hooksPath`. `commit-msg` rejects commits without active work or with
   trailers inconsistent with the state. Harness commits pass by construction.
5. Document the new rule in `AGENTS.md` template: any small edit opens `quick`
   automatically; the hook message tells the agent which command to run.
6. Tests: status artifact round-trip, divergence detection, history check with
   forged and missing trailers, hook rejection and acceptance, bootstrap
   installing hooks. Update `docs/acceptance.md` and `docs/HANDOFF.md`.

# Acceptance

- A manual `git commit` with no active work is rejected by the hook and, if
  bypassed with `--no-verify`, by `ways check --history`.
- `.ways/status.json` always mirrors `current.json`; a stale copy fails integrity.
- `scripts/check.sh` still passes on this repository after applying the plan.
- No existing test weakens; harness-generated commits need no changes.
